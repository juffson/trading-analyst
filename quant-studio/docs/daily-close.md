# 每日收盘看板

入口：原生桌面「研究工作区 → 每日收盘」，浏览器 `/#daily-close`。

## 读取来源

- 本机 `$CODEX_HOME/automations/*/automation.toml`（未设置时使用 `~/.codex`）。匹配现有三个收盘 heartbeat 的名称，读取启用状态、RRULE 和目标会话 ID；不会把 prompt 或其他配置返回前端。不修改计划，不另外启动研究。
- GitHub 研究目录的当前跟踪名单、标的目录和所有报告版本。逐市场、逐交易日统计不同标的的归档数量，同日取最高 revision。历史批次也按当前名单统计，页面注明此限制。
- `juffson/trading-analyst` main 的 `publish-feishu.yml` 最近 8 次 Actions 执行。仓库级记录，不冒充某个批次/标的的发布回执。成功只显示「执行通过」：当前工作流缺少发布配置时也可能正常退出。
- Notion 没有机器可读的同步回执，显示「待核验」。此页不读取 Codex 私有对话数据库或个人交易数据。

## 时间与状态语义

现有计划按 Asia/Shanghai 周规则计算。支持单个小时/分钟、每周指定星期；不能解析的规则明确报未知。工作日当日计划即使尚未到点也展示，周末沿用最近计划日。美股计划对应前一日交易日期。这里只推算日期，交易所假期、半日市和美股实际收盘仍由原任务核验。计划启用不等于正在执行，未归档不等于失败。

报告价位来自对应原始 JSON，不对缺失数值做推算；`unavailable` 不显示候选价位。上一期取更早交易日的最高修订，缺失目标价不计算差值。指数单位为点。详情在内置研究档案打开，并保留选中的交易日及修订版本。

## API 与刷新

- `GET /api/daily-close`：组合快照，GitHub 缓存 5 分钟，本机计划每次重新读取。
- `POST /api/daily-close`：仅接受本地 Origin，立即重新查询只读状态。
- 页面可见时每分钟查询一次；市场和日期切换保持可交互。报告详情最多 3 个标的并行加载，使用不可变报告版本缓存。
- 研究目录失败时沿用现有归档模块的 stale 快照并提示；发布 API 失败保留旧记录及原核验时间，明确标记缓存。首次失败不伪造完成度。

## 当前操作范围

可查看计划、最近计划批次完成度、历史批次、未归档名单、收盘/涨跌、目标变化、候选入场与止损止盈，以及发布执行日志。任务运行、补跑和发布重试仍在原 Codex 会话执行。真正的逐标的执行状态、飞书内容核验结果和 Notion 同步结果需后续由原流程输出结构化回执，不能由报告存在或 Actions 绿灯推断。

## 验证

Rust 测试覆盖计划到点前后、北京时间边界、周末、跨年美股计划和未知规则。Node 测试覆盖修订去重、市场/当前跟踪过滤、旧日期不借用未来报告，以及发布状态语义。浏览器验证市场切换、历史日期、未归档筛选、详情版本跳转、刷新与相邻页面。

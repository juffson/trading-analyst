# 纯分析研究站

本目录是 GitHub Pages 和飞书 Wiki 的共同研究数据源：每次分析只新增一个 JSON 文件，GitHub Actions 校验完整数据集后分别发布。页面按“总览 → 标的 → 日期报告”组织，并保留每次修订。

报告只包含公开市场和公司分析。提交前完成纯分析字段与公开来源检查；提交进入公开仓库后已经可见，不能依靠 Actions 再做脱敏。

## 数据与页面层级

| 数据 | 用途 |
| --- | --- |
| `symbols.json` | 标的、名称、市场、货币和页面 slug。 |
| `reports/<symbol>/YYYY-MM-DD.json` | 该交易日首次保存的报告，`revision: 1`。 |
| `reports/<symbol>/YYYY-MM-DD.v2.json` | 同一天新增的修订，原版保留。 |
| `schema.json` | 编辑器可用的 v1 JSON Schema。 |
| [CONTRACT.md](CONTRACT.md) | 完整字段、时间、质量、隐私和路径规则。 |

总览展示各标的最新分析与方向变化；标的页展示真实历史收盘价、已保存报告的判断记录与报告索引；日期页展示具体分析、证据、关键价位和限制。修订具有独立地址，日期入口打开该日最新修订。

行情走势与判断历史分别来自不同数据：`price_history` 仅保存真实历史收盘价；方向和分析价位仅来自实际保存的报告。新补录的历史分析使用真实 `generated_at`，不把今天的判断描绘为过去已经发布的预测。

## 新增一篇报告

1. 读取 `symbols.json` 和 [CONTRACT.md](CONTRACT.md)，确认标的已登记、市场及货币一致。
2. 获取目标交易日的可核验公开资料，确认市场已经收盘。生成完整合同对象，没有证据的数字用 `null`。
3. 新日期写入初版路径；同日已经存在时比较内容，重试相同工作不重复提交，需要修订才追加下一版本。
4. 提交前检查完整 JSON。使用本地环境时执行下方校验命令；Task 没有执行环境时仍须逐字段遵守合同，发布由 Actions 强制校验。
5. 通过 GitHub 创建一个新的报告文件。不要重写首页、索引或生成后的 HTML，构建器会从数据自动更新这些页面。
6. 读回文件并记录提交 SHA。分别检查 Actions 构建结果和 Pages 实际页面，按下一节判断完成状态。

```bash
python scripts/validate_research.py --root .
python -m unittest discover -s tests -p 'test_research.py'
python scripts/build_research_site.py --root . --output _site --base-path /trading-analyst
```

CI 的后续 push/PR 还应传入 `--base-ref`，对已有报告执行只追加规则。它拒绝覆盖或删除历史报告；修正数据必须新增修订。首次部署没有历史基准时只校验当前快照。

## 自动同步飞书 Wiki

独立工作流 [publish-feishu.yml](../.github/workflows/publish-feishu.yml) 将同一批已校验分析发布到指定 Wiki 入口下的“复盘分析（自动发布）”分支，包含总览、标的主页、日期及修订文档，以及真实历史价格趋势图。它不读取原入口正文，也不修改原来的分析任务。

先按 [FEISHU.md](FEISHU.md) 配置自建应用和三个仓库 Secrets，再从 Actions 手动运行 `check`，确认只读访问后运行 `publish`。没有凭据时可以先运行 `validate`，该模式不会调用飞书。配置完成后 `main` 上新增分析会触发自动同步；未配置时自动发布明确跳过。

```bash
python -m pip install -r requirements-feishu.txt
python -m unittest discover -s tests -p 'test_*.py'
python scripts/publish_feishu.py --root . --mode validate
```

飞书入口、文档标识和应用凭据不进入公开研究 JSON、生成的 Pages 或 Actions 附件。飞书发布成功必须看到 API 写入后的实际回读验证，单纯通过本地测试或 `check` 不能代表已发布。

## 可复用的 Task 提示模板

下面是新建分析任务的提示模板。运行时间、目标交易日和标的应由任务配置明确给出；模板本身不会创建或修改任何任务，也不会改动原来的 Notion 流程或会话。

> 在 GitHub 仓库 `juffson/trading-analyst` 的 `main` 分支追加一篇纯分析报告。
>
> 目标标的：`<SYMBOL>`。目标交易日：`<YYYY-MM-DD>`，使用对应市场当地日期。若是每日任务，则先确认当地最近已经收盘的实际交易日，休市日不冒充新交易日。
>
> 先读取当前 `research/CONTRACT.md`、`research/schema.json`、`research/symbols.json` 和目标标的已存在的报告文件，按仓库当前合同完成工作。只接受已登记标的。读取上一份公开分析用于比较；不要读取或调用个人账户、持仓、成交、盈亏或资产工具，不要把 Notion、飞书等内部文档链接带入公开内容。
>
> 用可核验的市场与公司公开信息形成分析。优先获取目标交易日的历史 K 线或收盘记录，不能把当前报价作为旧日期收盘价。记录行情截止时间、实际生成时间、公开来源和资料限制。`trade_date`、`data_as_of`、`generated_at` 分别填写，其中 `data_as_of` 专指行情截止时间。收盘后资讯另用来源的 `published_at` 注明，并明确其收盘后属性，不用于倒推当天价格原因。历史补录用 `provenance.kind: historical_backfill`，当期新分析用 `fresh_analysis`。
>
> 严格使用 v1 白名单字段生成完整报告。不能获得收盘数据时采用 `blocked + Unknown`，具体原因写入 `limitations`；不把缺证据伪装成 `Neutral`，不虚构收盘价、指标、目标位或历史预测。分析价位必须具有依据、类型、期限以及适用的触发和失效条件。已有历史价格只用经核验的数据。
>
> 提交前对完整 JSON 做字段、个人信息、私密链接、HTML/脚本协议、日期、价格和来源检查。如果存在 Python 执行环境，运行仓库校验器；没有执行环境时不得声称已运行校验器，等待 Actions 的实际结果。
>
> 新交易日只创建 `research/reports/<SYMBOL>/<YYYY-MM-DD>.json`，`revision: 1`。如果路径已存在，先读回并比较：相同任务的幂等重试直接返回已有结果；需要修订则创建下一连续 `.vN.json`，保留旧文件。每次运行只提交一个报告 JSON，不更改合同、构建器、工作流、标的登记表或旧报告。不要覆盖同日原版。
>
> 写入完成后从 GitHub 重新读回精确路径，核对内容并记录提交 SHA。然后查询该提交对应的 Actions 与 Pages。回复时分别说明“报告已提交并读回”“Actions 校验/构建结果”“Pages 页面是否已实际可访问”；尚未发生的阶段写“待验证”，不要把当前会话写入成功当作后台 Task 已验证，也不要把提交成功等同于网站发布成功。

对多个标的的每日工作，可以为各标的分别执行上述单报告步骤；每篇报告保持独立文件、独立身份。调整旧任务需要单独授权，本仓库的新增流程不要求修改它们。

## 如何认定验证完成

| 阶段 | 必须看到的证据 | 还不能证明的事项 |
| --- | --- | --- |
| 普通会话写入 | GitHub 返回实际提交 SHA，精确路径读回内容一致。 | 后台 Task 是否具有同样工具和写入权限。 |
| 后台 Task 写入 | 独立任务实际运行，目标报告由该次运行创建；读回路径、内容和提交记录可核对。 | Actions 或 Pages 是否成功。 |
| Actions 校验与构建 | 对应提交的 workflow 成功，完整数据校验通过，站点构建成功。 | 页面是否已经对外可访问。 |
| Pages 部署与访问 | 对应部署成功；线上总览、标的页、日期页和数据链接均实际打开且可互相跳转。 | 下一次 Task 运行一定成功；后续运行仍应报告失败。 |
| 飞书 Wiki 发布 | `publish` 实际写入后回读全部正文与图片绑定，最终同步总览和标的目录。 | `validate` 或只读 `check` 不证明写入和媒体权限；下一次运行仍须检查。 |

这张表定义验收标准，不代表各阶段已经完成。失败时保留已完成阶段的证据，准确指出停在哪一阶段，不把未执行的工作标为成功。

## 校验范围

Python 校验器只依赖标准库，执行严格字段检查、标的与货币匹配、带时区时间、已收盘时间、有限数值、报价关系、历史日期顺序、路径身份和修订连续性。它拒绝额外账户/持仓/交易字段、明显个人持仓文本、内部文档链接、带凭据 URL、非公开网络地址、HTML 和脚本 URL；原始 JSON 的全部字段都检查，不只检查页面显示的内容。错误日志不回显敏感字段值。

可选 `--base-ref <完整提交SHA>` 使用 Git 对比基准，阻止改写或删除已存在的报告。静态页构建只读取通过校验的研究文件，不从仓库其他目录抓取分析材料。

校验器不内置各交易所节假日日历，也不联网证明来源内容真实。生产者须核实交易日、数据口径与来源；无法确认的内容应明确降级或阻塞。
